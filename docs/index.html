Three things it does properly

The app is small on purpose. What it does, it does without waiting.

01 — READ

Verbatim, chapter by chapter

Each book opens on its own contents — Kent's thirty-four chapters, Knerr's forty-three, Gentry's A–Z of concordance keywords. Rubrics appear in the printed order with the remedies the book itself sets beside them, and the printed grade marks where the source carries them.

02 — SEARCH

Inside a chapter, then a volume, then everything you have opened

Type two letters and the chapter answers; widen the scope and it searches every volume already on your device. Remedy names are searched too, so nux-v finds the rubrics that carry it.

03 — FOLLOW

Every remedy is a door

Tap any remedy chip to see every rubric in that volume which lists it, or open the remedy rail to read a volume by its drugs instead of its chapters. That is the whole navigation model: text, and the remedies in it.

What it refuses to do

A repertory is evidence. The moment a reader starts scoring, guessing or completing, it is no longer evidence.

  • No repertorisation. No remedy scoring, no case analysis, no "most indicated". The books rank nothing; neither does the reader.
  • No editing. There is no way to change a rubric, add a remedy or correct the OCR. What you see is what the volume says.
  • No accounts, no server, no tracking. No analytics, no fonts from anywhere, no cookie. Open it and read.
  • No network after the first page. Chapters you have opened are kept on your device; the reader works with the connection off.

Run it yourself

One HTML file and three small companions. No build step, no package manager, no bundler — and it is deliberately locked against one.

git clone https://github.com/drsamonline/repertory-reader
cd repertory-reader/docs && python3 -m http.server 8000
# open http://localhost:8000/play/

# reading a local mirror of the library instead of GitHub:
#   play/?lib=../lib/     (the library's files, copied under your web root)

The app is hand-built and stays that way: there is no CI, no build workflow, and no packaging into an EXE or an APK. See LOCKED.md.
